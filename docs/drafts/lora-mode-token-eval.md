## 三、初步观察（供 eval 验证或推翻）

1. **开销主要不是"文本税"而是"行为税"**：lora-mode 全部文本（SKILL.md+1 个 playbook+协议）约 20KB 中文 ≈ 2-4 万 token；而 A/B 差额是 17-32 万——大头是多出来的步骤：todo 仪式、证据表格、协议/门禁文件整读、更长的探索与复验、7 段式报告。
2. **小任务是重灾区**：publish（本身流程短）只花 156k，而同样规模小的 backend 花了 267k——差异在于 backend 走了完整七步+审查降级自查。小任务上"七步+强制审查+证据模板"是纯税。
3. **大任务上流程可能回本**：teaching-page 的对抗审查抓到 reduced-motion 真 bug、static-site-release 抓到自引入对比度回归——这些返工在基线模式下未必发生；但本数据集没有大任务基线，无法直接证明回本。
4. **报告格式税**：测试要求的 7 段式报告本身不便宜，但这部分是测试成本，不是技能成本——eval 时应剔除。

## 五、v0.4 落地与复测（2026-10-06）

评审子代理（351,499 tokens）产出精简方案，已全部落地：

1. **规模分级 S/M/L** 写入 SKILL.md（一处定义，playbook 零增量）：S 档不读 playbook/references、四步、3 行证据、行内三维点查；M 档七步 + 行内自查卡（约 250 token 替代整读协议 1.9k）；L 档全量。升级锚点写死（>2 文件/新依赖/公共组件/公开 → 宁大勿小），publish 类永不进 S 档。
2. **SKILL.md 瘦身**：13,381 → 10,691 字节（约 4,050 → 3,200 token）。使用规则 6→4、原则 12→6（概念全保留）、分工速查主导行合并、交付模板改按档位、示例 2→2 行、删结尾引言。
3. **references 时机收紧**：review-protocol 仅 L 档整读；quality-gates L 整读 / M 读证据矩阵节 / S 不读。
4. **oil-ui 双装修复**：.zcode 与 .agents 副本逐字节相同，删 .zcode 冗余副本。
