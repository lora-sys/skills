# autonomous-run — 持续执行与无人值守任务

> **适用**：用户明确要求"继续做到完成/不要中途停下/做完再回报"，或任务需要无人值守、多阶段等待。普通单阶段任务遵循 `SKILL.md` 的完成契约，不额外加载长任务流程。**主导 skill**：无（执行方式，不替代任务类型）。

## 步骤

1. **先定完成条件与边界。** 将用户要求转成可检查的验收条件，并列出必须暂停的权限边界、真正外部阻塞和需要用户决定的实质性选择。自主执行不扩大授权。
2. **拆分并留检查点。** 多阶段任务用 todo 跟踪全部验收项；每阶段结束记录完成证据和剩余工作。单阶段任务不为此创建长 todo。
3. **后台执行长步骤。** 构建、批量生成、多文件改造 → 后台运行；主线程推进不依赖它的步骤。
4. **失败后换路继续。** 先定位失败原因，修复授权范围内可控的问题；用不同且有意义的方法尝试恢复，避免无变化地重跑同一失败命令。同一根因最多尝试三种有效路径；仍无法解决时记录现场，继续独立工作并列明阻塞与下一步。
5. **阶段汇报不是收尾。** 每个阶段后回到验收条件，继续所有未完成且可做的项目。工具、搜索、测试或依赖失败本身不构成停止条件。
6. **只在真实边界暂停。** 遵循 `SKILL.md` 的权限限制；需要用户决定的实质性产品选择、真正外部阻塞或用户明确取消时说明原因和所需输入。其他可逆决策由 Agent 自行作出并记录。
7. **收尾验收（强制）。** 有具体任务类型时，只执行其 playbook 尚未完成的验收与审查步骤，不重复已跑的质量门或 reviewer；没有专属 playbook 时，按改动风险选择 `../references/web/quality-gates.md` 中相关门，并遵从 SKILL.md 的 M/L 审查档位。
8. **按证据交付。** 逐项说明完成状态、产物、实际运行的验证、未解决阻塞和下一步；不得把未运行、跳过或仅部分通过说成完整通过。

## 证据形态

决策日志、后台任务输出、验收证据、"等用户"清单。

## 移交

任务本身所属的 playbook（autonomous-run 是执行方式，不是任务类型）。
