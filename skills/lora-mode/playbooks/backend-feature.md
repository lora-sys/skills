# backend-feature — 后端服务、API、脚本与工具

> 继承 SKILL.md 七步骨架与硬边界，本文件只写每步的具体动作。
> **适用**：后端服务、API、CLI 脚本、数据处理工具、爬虫类开发。**主导 skill**：无专门 skill，靠骨架 + debug 纪律。

## 步骤

1. **识别现状。** 运行方式（本地/部署）、语言与依赖管理、现有入口、配置与凭据来源、输出消费方。
2. **核实技术事实。** 库与运行时版本查官方文档；CLI 参数用 `--help` 验证，不凭记忆。
3. **出计划。** 接口契约或 CLI 约定（输入/输出/退出码）、数据模型、错误路径、日志、依赖变更、验收项。通用问题先路由到同目录 `investigation.md` 找成熟方案（拿到结论后回到本 playbook 继续），不重复造轮子。
4. **实现。** 数据形状先行；外部输入一律验证结构与边界；显式错误处理，不吞异常；机密只从环境读取。
5. **验收（强制）。** 真实运行：主路径 + 成功/失败/空/异常路径各跑一遍，留命令与输出；有测试就跑测试；新工具类任务给一条可复制的运行命令。
6. **隔离对抗审查（强制）。** 按 `../references/review-protocol.md`；重点维度：类型与外部输入、安全与隐私、性能与可靠性。
7. **按证据交付。** 运行输出、测试结果、日志片段；说明适用范围与未做路径。

## 证据形态

真实命令与输出（成功+失败路径）、测试结果、错误路径演示。

## 移交

需要 Web 界面配套 → `web-feature.md`；需要上线 → 与用户确认部署方式后走对应发布流程（本 playbook 不含部署）。
