# bug-fix — 排障与根因修复

> 继承 SKILL.md 七步骨架与硬边界，本文件只写每步的具体动作。
> **适用**：bug、报错、崩溃、卡死、行为不符、性能回退、"为什么/怎么回事"。**主导 skill**：debug（全程主导）。

## 步骤

1. **加载 debug skill 并按其全程执行。** 本 playbook 是 debug 纪律的调度壳；两者冲突时以 debug 为准。
2. **最小化复现。** 能用脚本/单测复现的不用浏览器，能三个步骤复现的不用十步；复现失败就继续收敛条件，不猜。
3. **定位。** 二分（git bisect、路径中点观测、栈采样）；每轮观测记录"假设—预期—实际"。
4. **假设与验证。** 一次一个假设，验证后才动手改；不跳到"可能是 X"就开改。
5. **根因处最小修复（强制）。** 先有失败测试再修（测试形态不拘：pytest、裸断言、独立复现脚本均可，红→绿必须真实）；根因三条件不满足就继续挖；禁止吞异常、特判绕过、sleep 藏竞态、返回默认值糊弄。
6. **复验 + 回归面。** 原复现路径验证修复；检查共享状态、公共组件、全局配置是否被误伤；受影响验收步骤重跑。
7. **教训沉淀（强制）。** 把本次教训追加到 debug 的 lessons.md；同类问题第二次出现，升级为对应 skill/references 的硬规则。目标文件不可写（权限/沙箱限制）时，把教训原文附在交付报告里并注明"待补写进 lessons.md"。
8. **按证据交付。** 复现步骤、根因解释（能讲清为什么以前能跑）、修复 diff、复验输出。

## 证据形态

最小复现物（脚本/步骤）、根因链条（假设→验证→结论）、失败测试、复验输出、lessons 追加记录。

## 移交

修复暴露更大改造需求 → `web-feature.md` / `backend-feature.md`；顺手可修的相邻问题单独列出不扩张。
