# investigation — 只读调查、技术选型、"这是怎么做到的"

> 继承 SKILL.md 七步骨架与硬边界，本文件只写每步的具体动作。
> **适用**：只读调查、选型对比、机制解释；不改任何代码。**主导 skill**：无（平台子代理 + github-gem-seeker）。

## 步骤

1. **定义问题。** 一句话问题 + 判定标准（"什么答案算够用"）；范围外问题明确排除。
2. **仓库内侦察。** 批量读文件/追线索 → 派 Explore 子代理，只要结论不要文件转储；主线程留决策。无法派子代理时行内侦察，并在交付中注明。
3. **外部找方案与核实。** 找成熟开源方案时调度 github-gem-seeker（stars/活跃度/文档评估）；技术事实与版本核实直接查官方文档——两者分工不同，不互相替代；不凭记忆。
4. **交叉验证。** 结论至少两个独立来源；冲突时标出分歧与各自证据。
5. **按证据交付。** 结论先行 + 证据清单（链接、文件:行号、命令输出）+ 建议（含"不必做"的建议）；全部只读，不改代码。

## 证据形态

来源链接、file:line 引用、真实命令输出；每个结论可溯源。

## 移交

调查结论要动手 → `web-feature.md` / `backend-feature.md` / `bug-fix.md`；发现是 bug → `bug-fix.md`。
