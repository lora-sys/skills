# prototype — 抛弃型原型

> 继承 SKILL.md 七步骨架与硬边界，本文件只写每步的具体动作。
> **适用**：只为便宜地定设计/行为/技术决策，产物本身不进生产。**主导 skill**：无，最快路径优先。

## 步骤

1. **写下唯一要决策的问题。** 一句话（"侧边栏目录还是顶部目录更适合长文？"）；回答不了这个问题的活不做。
2. **核实事实。** 只核实影响决策的部分（某 API 能不能做到、某动效顺不顺滑）；其余不查。
3. **最快路径实现。** 默认单文件 HTML 或现有栈最小骨架；硬编码数据没问题；不写测试、不配 CI、不做发布准备。
4. **自测到"能点"。** 浏览器实际点过主要交互；原型也要真实运行，不摆样子。
5. **记录结论（强制）。** 结论落成原型目录下的 `decision-record.md`（采用什么、为什么、扔掉什么、对正式实现的约束），并在交付回复里给要点；原型代码本身默认抛弃。
6. **交付与处置。** 给用户可打开的原型路径 + 结论；用户拍板后按结论转 `web-feature.md` / `ui-design.md` 正式实现；原型留在沙箱目录，不混入生产仓库。

## 证据形态

可打开运行的原型路径、决策结论记录、与备选方案的取舍说明。

## 移交

决策完成 → `web-feature.md`（正式实现）或 `ui-design.md`（需设计深化）。
