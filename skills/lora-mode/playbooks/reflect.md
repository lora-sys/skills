# reflect — 复盘与自我迭代

> 继承 SKILL.md 硬边界；本 playbook 是 lora-mode 自我迭代的唯一入口。
> **适用**：用户说"复盘/迭代技能/沉淀一下/更新 playbook"；或 SKILL.md 交付钩子的自动触发条件命中（本次出现 bad case、同会话二次同类纠正、台账自上次 reflect 以来 ≥5 条真实任务行）——命中即自主进入，不需用户点名。**主导 skill**：skill-creator（产新 skill 时）、github-gem-seeker（先找轮子）。

## 数据源（没有证据不立项）

1. `../USAGE.md` 运行台账：场景、档位、消耗、摩擦记录（该文件不入库；首次安装或本地无台账时，以本会话摩擦为唯一证据来源）。
2. 本次会话的原始摩擦：用户重复解释了什么、哪一步绕路、哪个检查救了场/纯属仪式。
3. `docs/drafts/` 评测文档与 debug 的 lessons.md。

## 步骤

1. **汇集证据。** 读 USAGE.md 最近条目 + 本会话摩擦；把候选改进列成清单，每条必须引用至少一条记录，无引用的丢弃。
2. **三类出口分流。**
   - **小修**（措辞、步骤增删、阈值调整，单处 ≤5 行）：直接改对应 playbook/references，USAGE.md 追加修订记录行，同步安装副本。一次复盘最多 3 处。
   - **结构性改动**（新增/合并 playbook、改分级规则、改硬边界）：只出方案与证据，用户拍板后再动。
   - **新 skill**（同样的事第三次出现、或 github-gem-seeker 找到的现成方案值得固化）：路由 `skill-authoring.md`（skill-creator 主导）走完整造 skill 流程——草案落本仓库、跑测试 prompt、用户决定是否提交。不跳过测试直接装。
3. **执行小修并记账。** 每处改动在 USAGE.md"修订记录"追加一行：日期、证据来源、改了什么。改完同步 `~/.agents/skills/lora-mode/`。
4. **复测（强制）。** 改动影响哪个 playbook，就跑 `../evals/EVALS.md` 中该 playbook 的 case（每 case 一个全新子代理；派不了子代理时行内复测——同 E11 降级口径，并在修订记录注明，不冒充盲测）；结构性改动、版本发布或用户点名"跑 eval"时跑全量。结果（日期、case、PASS/FAIL、用量）记入 USAGE.md 修订记录；FAIL 先回滚改动再排查。
5. **按证据交付。** 本次改了什么、依据哪些使用记录、待用户拍板的方案有哪些、台账最新状态。

## 纪律

- 禁止无使用证据改技能——"我觉得"不是证据。
- 禁止一次复盘超过 3 处小修；剩下的列入 USAGE.md 待办，下次复盘再议。
- 新 skill 与结构性改动必须用户拍板；小修可自治但全部留痕、可回滚（git）。
- 复盘本身是 M 档任务；改后复测才允许交付。
