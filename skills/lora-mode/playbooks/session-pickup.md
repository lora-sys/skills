# session-pickup — 接手、恢复、继续之前的工作

> 继承 SKILL.md 七步骨架与硬边界，本文件只写每步的具体动作。
> **适用**：接手上次没做完的活、恢复中断任务、换会话续作。**主导 skill**：无（平台内置工具为主）。

## 步骤

1. **收集现场。** 有 `#sess_*` 引用 → ReadSessionContext（relevant 或 handoff）；没有就只看磁盘现场，不凭空脑补上次做了什么。
2. **看仓库状态。** git status / log / diff、未提交文件、临时文件与日志。注意 TodoRead 只见本会话 todo，接手场景拿不到上次进度，跨会话状态以磁盘现场（第 1 步）与 git 为准。
3. **重建 todo。** 把"已完成 / 进行中 / 未开始"列成 todo，标明证据（哪个提交、哪个文件、哪条输出支持"已完成"）。
4. **向用户确认起点（唯一允许问的一步）。** 报告："上次停在这里，接下来我打算先做 X"——用户默许或纠正后继续；无应答（异步/自治场景）按计划继续，并在交付中标注"起点未经确认"；除这一步外照常自治。
5. **续作。** 按现场所属任务类型重新路由到对应 playbook（通常用户会直接说，路由不了就按第 4 步的建议走）；交接只带产物与验收状态，不重开计划。续作 diff 很小（约 ≤10 行）时，可在承接的 playbook 内声明压缩审批式步骤，但验收与证据交付不减。
6. **按证据交付。** 恢复了什么、依据什么证据、接下来做什么。

## 证据形态

git/文件系统的现场证据、上下文恢复摘要、重建的 todo。

## 移交

确认任务类型后 → 对应 playbook（web-feature / bug-fix / …）。
