# static-site-release — 存量静态站体验改造与发布

> 继承 SKILL.md 七步骨架与硬边界，本文件只写每步的具体动作。
> **适用**：已上线的个人站/作品集/博客的体验改进、内容对齐、发布验收。**主导 skill**：static-site-experience-release。

## 步骤

1. **识别现状。** 加载 static-site-experience-release 并按其全程执行；建隔离分支，确认基线（用户已确认的视觉基线不动）。
2. **访客路径审计。** 沿真实访客路径过一遍：P0 事实错误 → P1 阅读摩擦 → P2 微交互；禁止堆功能。
3. **出计划。** 审计发现按 P0/P1/P2 排序成改造清单，逐条可验证。
4. **克制实施。** 事实与信息层级修正优先，交互改进克制；日期、成就、数字一律不编造。
5. **验收（强制）。** 本地生产预览（零构建静态站：起本地静态服务器服务站点根目录即视为等效）+ Lighthouse；走 `../references/web/quality-gates.md` 中适用的门禁（内页 SEO、无障碍、移动端）。本地服务器造成的环境性扣分（缓存 TTL、HTTP/2 等）标注"环境性"，不在无部署预览时强追。
6. **用户批准（强制，硬边界）。** 改动清单 + 前后截图给用户，批准后才 merge/push；绝不伪造访客数据、不发测试评论。
7. **线上验收。** 合并推送后打开线上站复验核心路径；按证据交付。

## 证据形态

审计清单（P0/P1/P2）、前后截图、Lighthouse 输出、线上复验截图。

## 移交

单页新产出要另发链接 → `publish.md`；发现 bug → `bug-fix.md`。
