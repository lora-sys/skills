# web-feature — 前端 / 全栈 Web 功能与页面

> 继承 SKILL.md 七步骨架与硬边界，本文件只写每步的具体动作。
> **适用**：新建或改造 Web 应用、页面、组件、交互。**主导 skill**：oil-frontend（实现）、oil-ui（设计判断）。

## 步骤

1. **识别现状。** 读仓库约定、package.json/锁文件、脚本、现有组件、部署配置；判定新建 vs 改造。改造项目保留既有架构与工具，不为新而迁移。
2. **核实技术事实。** 新建项目、升级依赖或用不熟悉 API 前，查官方文档与当前稳定版本；不凭记忆写版本、命令或 API。
3. **出计划。** 简洁主上下文摘要：目标与非目标、用户流/信息架构、选型依据、页面与组件、状态与数据/API、依赖变更、风险、验收项、部署状态。选型读 `references/web/stack-selection.md`。
4. **设计判断（按需）。** 涉及新界面、视觉方向或多风格选择时，先调度 oil-ui 出对比页，用户选定后再动工；纯逻辑改动或小改动可跳过，但须在 todo 记录原因。视觉/动效标准读 `references/web/design-motion.md`。
5. **实现最小正确变更。** 调度 oil-frontend；数据形状先行（先写状态与数据结构，再写界面）；按项目结构与命名实施；发现相邻问题记录不顺手修。
6. **验收（强制）。** 读 `references/web/quality-gates.md` 执行门禁：真实构建/类型/测试输出；成功、加载、空、错误路径；真实浏览器窄屏+宽屏截图；性能、SEO、无障碍按矩阵评估。
7. **隔离对抗审查（强制）。** 按 `../references/review-protocol.md` 新开零上下文审查；只修经源代码或运行事实验证为真的问题，修后复验。
8. **按证据交付。** 前后截图（UI 变更）、动效给录屏；按 SKILL.md"交付"模板汇报。

## 证据形态

构建/测试真实输出、浏览器前后截图（窄+宽）、录屏（动效/多步交互）、审查核验记录。
