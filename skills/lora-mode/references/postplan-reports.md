# Postplan 报告触发与发布

## 按场景选择

- 明确的 PR 代码审查和架构审查默认准备一份独立 HTML 报告。复用已核实的 findings、证据、风险和建议，不重复跑分析，也不把完整 diff 或源码复制进报告。
- 普通 PR 创建、Issue 草拟/分诊和 PR 跟进默认使用正文内 Mermaid 图与简短正文，不额外生成 Postplan。
- 用户明确要求独立报告，或结论包含多项发现、证据和方案比较，正文或评论难以清楚承载时，准备 Postplan 报告。
- 报告关联 PR / Issue 时，把已发布的公开 URL 放入正文草稿。仅在用户明确授权远端写入时更新 PR / Issue；否则交付链接和可粘贴的一行文字。
- 如果用户要求把公开 Postplan URL 写入 PR / Issue 正文，先按默认流程发布报告并取得真实 URL，再写入已授权的正文；不要填占位 URL。报告只是补充材料且正文可独立成立时，可继续其他已授权工作。

## 公开发布门

- Postplan 页面公开。先完成 HTML 并运行 `html-communication` 的 preflight，再检查最终公开内容和资源。
- 标准 Postplan 公开 draft 默认直接新建或更新，无需额外逐次确认。用户明确要求本地交付或不上传时，交付本地版本；若无法安全判断公开内容，先暂停并澄清。
- 报告不得包含凭据、私密源码、私有 Issue 原文、真实用户数据或内网 URL。能安全删减时先制作脱敏公开版再发布；无法在不泄露私密信息的情况下形成有用报告时，不上传，交付本地安全版本并说明原因。
- Postplan 发布不授权 PR / Issue 正文、评论或状态的远端写入；这些操作仍须用户明确授权。
