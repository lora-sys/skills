# Postplan 报告触发与发布

## 按场景选择

- 明确的 PR 代码审查和架构审查默认准备一份独立 HTML 报告。复用已核实的 findings、证据、风险和建议，不重复跑分析，也不把完整 diff 或源码复制进报告。
- 普通 PR 创建、Issue 草拟/分诊和 PR 跟进默认使用 SVG 图与简短正文，不额外生成 Postplan。
- 用户明确要求独立报告，或结论包含多项发现、证据和方案比较，正文或评论难以清楚承载时，准备 Postplan 报告。
- 报告关联 PR / Issue 时，把已批准的公开 URL 放入正文草稿。仅在远端写入另有授权时更新已有记录；否则交付链接和可粘贴的一行文字。
- 如果用户明确要求把公开 Postplan URL 写入 PR / Issue 正文，先保留正文草稿，等该版本获准发布后再写入；不要创建缺少所需链接的正文或填占位 URL。报告只是补充材料且正文可独立成立时，可继续其他已授权工作，并说明报告暂为本地版本。

## 公开发布门

- Postplan 页面公开。先完成 HTML 并运行 `html-communication` 的 preflight；向用户展示报告主题、公开范围和将上传的内容，再暂停取得本次发布确认。
- 每次新建或更新公开页面都要重新确认。过去的授权、`full-stop`、`full-send` 和 PR/Issue 写入授权均不代替本次确认。
- 未获确认或用户拒绝时，不上传；交付本地 HTML 或 Markdown 报告，并说明公开链接尚未生成。
- 报告不得包含凭据、私密源码、私有 Issue 原文、真实用户数据或内网 URL。无法在不泄露私密信息的情况下形成有用报告时，停止公开发布并交付安全的本地版本。
