# 项目 AGENTS.md

项目 `AGENTS.md` 是常驻上下文。流程由 lora-mode 与项目内 skill 承担；本文件只补充项目事实。

## 判据

按顺序判断，命中即停：

1. 能机械执行 → lint 或 CI 规则；正文只留一句「由 `<rule>` 强制」。
2. 读代码、`package.json` 或配置能得出 → 删掉。
3. 与具体仓库无关的通用偏好 → 全局 AGENTS.md。
4. 超过 5 步的流程 → `.agents/skills/<name>/SKILL.md`；正文只留指针。
5. 只有本仓库成立，且违反代价高 → 写入项目 AGENTS.md。

预算：单仓库不超过 150 行。超出的内容按第 4 条拆走。

## 硬性要求

- 第一段写优先级。项目文件的明确禁令必须覆盖 skill 的默认流程；否则 agent 会按默认流程自行开 PR、跑全仓检查、往仓库写检查点。
- 每条约束写成可检查的事实。反例「注意性能」；正例「列表超过 200 项必须虚拟化，CI 有 benchmark 门槛」。
- 命令必须能从干净 checkout 复现，并写明工作目录。
- 陷阱写明会坏什么。只写禁止动作，agent 会当成风格建议忽略。
- 不写密钥、内网地址、个人链接。

## 反面清单

- PR-only、禁止直推默认分支、变更影响图、证据对应最新 head、S/M/L 分级：lora-mode 已有。重复会分裂成两套真相。

- 完整 runbook：放 `docs/`，正文留链接。
- 历史沿革与决策过程：放 ADR 或 PR 描述。
