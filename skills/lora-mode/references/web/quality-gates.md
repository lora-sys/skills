# Web 项目验收门禁

按改动风险选择相关门禁；本文件不是每个 Web 任务都要跑一遍的全量清单。所有结论以实际命令、交互结果或可复核截图为准，未做的检查明确标注。

## 默认验收

1. 先检查项目已有脚本、CI 和约定，不捏造通用命令或引入只为检查服务的依赖。
2. 运行覆盖本次代码路径的现有类型、测试、lint 或构建检查；验证改动的主路径及本次涉及的失败/边界状态。
3. UI 或交互改变时，在能触发变化的真实状态下验证；布局变化再检查受影响的窄/宽视口。截图只用于可见改动、用户要求或确实能帮助复核的场景。
4. 按下表追加专项检查。没有关联风险的门禁不运行，也不写成长篇“不适用”清单。

## 按风险追加

| 门禁 | 何时执行 | 最小证据 |
|---|---|---|
| 响应式与视觉 | 布局、主题或视口相关行为改变 | 受影响视口下的真实检查；有可见差异时提供前后截图 |
| 键盘与无障碍 | 新增/改变交互控件、表单、模态或动态状态 | 键盘完成主路径，焦点/名称/错误状态可辨认 |
| 性能 | 优化任务，或改动影响大列表、媒体、Canvas/3D、重复请求等成本 | 受影响路径的测量或可复现观察 |
| SEO | 可公开索引页面的路由、主要内容或元数据改变 | 页面标题、语义和抓取相关输出 |
| 安全与隐私 | 认证、权限、敏感数据、外部输入或凭据路径改变 | 对应输入/权限边界的检查结果 |

公开发布、生产部署或用户明确要求时，才跑完整质量矩阵。公共站点按实际公开路由检查 SEO；内网、原型和工具按其真实用户面选门禁。

## 不重复审查

独立审查由 SKILL.md 的 M/L 档位和对应 playbook 决定。本文件只定义验收检查，不额外触发 reviewer；PR 创建/审查沿用各自 playbook 的审查步骤。

## 交付摘要模板

| 项目 | 事实 |
|---|---|
| 已完成 | 用户可见行为和主要改动范围 |
| 范围 | 已实现、未做及原因 |
| 验证 | 实际命令、路径、视口或截图及结果 |
| 审查 | 实际发现、核验、修复或未解决项 |
| 限制 | 未验证路径、外部依赖和阻塞 |
| 发布 | 当前准备状态；部署仍按本次授权执行 |

静态页验收前硬刷新或禁缓存，避免旧副本造成假通过。交互依赖滚动、悬停或溢出时，构造能触发的最小状态并记录方式。
